# Termirai 需求说明书

> 本文档已与实现现状对齐（勾选 = 已实现并通过 e2e 验证）。

## 1. 项目概述

Termirai 是一个基于客户端/服务端（C/S）架构的**跨平台多机终端远程管理与 AI 操作平台**。

用户通过浏览器访问服务端 Web 控制台，即可：
1. 同时打开并操作多台客户端机器（Windows / Linux / macOS）上的多个终端（xterm.js），新建终端时可按客户端实际环境选择 shell 类型；
2. 浏览、管理客户端文件，并用 Monaco 编辑器直接编辑客户端上的文本文件；
3. 通过内置 AI Agent，用自然语言指挥其操作**一个、多个或全部**客户端的终端（可跨平台混编），支持全自动执行或人工审批执行。

## 2. 总体架构

```
浏览器 (React + shadcn 风格 UI + xterm.js + Monaco)
        │  HTTP / WebSocket（JWT，/api/v1）
        ▼
服务端 Server (Go，embed 托管前端，JSON 文件持久化，无数据库)
        │  WebSocket 长连接（注册 / 鉴权 / 心跳 / 终端 IO / 文件操作 / AI 指令）
        ▼
客户端 Agent × N (Go，Windows / Linux / macOS，每台机器一个)
```

- 浏览器 ↔ 服务端：HTTP（REST API）+ WebSocket（终端 IO 流、AI 流式输出、审批交互）。
- 服务端 ↔ 客户端：由客户端主动发起的 WebSocket 长连接（客户端可位于 NAT 之后），承载终端 IO、文件操作请求与 AI 下发指令，支持断线自动重连。
- 前端构建产物通过 Go `embed` 由服务端直接托管，单二进制部署。
- 终端由独立的 holder 子进程托管：unix 平台为 PTY（creack/pty）+ unix socket；Windows 为 ConPTY + 命名管道（go-winio）。agent 与 holder 间为自定义帧协议（数据/resize/kill/退出/回放），holder 内置 256KB 滚动缓冲。

## 3. 技术栈

| 模块 | 技术 |
|---|---|
| 服务端 | Go，gorilla/websocket，JSON 文件持久化（无数据库） |
| 客户端 | Go 跨平台：Windows 10 1809+（ConPTY + 命名管道 holder）/ Linux / macOS（creack/pty + unix socket holder） |
| 前端 | React + Vite + TypeScript + Tailwind CSS（shadcn 风格组件） |
| 终端组件 | xterm.js（含 fit / web-links 等插件） |
| 编辑器 | Monaco Editor |
| AI | OpenAI 兼容接口（tool-calling），支持 Web 端在线配置 |
| 配置 | 全部通过 `.env` 文件，**不使用任何数据库** |

## 4. 功能需求

### 4.1 客户端（Agent）

- [x] 通过 `.env` 配置：服务端地址、注册密钥、客户端名称（可选，默认主机名）、数据目录、shell（可选）。
- [x] 启动后主动向服务端发起 WebSocket 连接并注册，**鉴权密钥正确才允许接入**；密钥错误则拒绝并延时重试。
- [x] 断线自动重连（退避），定期心跳保活。
- [x] 终端能力：按需创建/销毁终端会话，同一客户端支持**多个终端并发**；转发终端输入输出；支持窗口大小调整（resize）。
- [x] **多平台 shell**：启动时探测本机可用 shell 列表并随注册上报（unix：`$SHELL` + bash/zsh/fish/sh 等，符号链接去重；Windows：`%SHELL%` + PowerShell/pwsh/CMD/Git Bash）；新建终端可指定 shell，agent 按上报白名单校验后由 holder 以指定 shell 启动，非法 shell 拒绝。
- [x] **终端会话常驻**：终端由独立 holder 子进程托管，生命周期独立于任何连接——Web 端断开、用户退出登录、与服务端的连接中断、甚至 agent 进程重启，终端都继续在客户端运行；**只有用户在 Web 端显式关闭终端（或 shell 进程自身退出）才销毁**。
- [x] 每个 holder 维护 256KB 滚动输出缓冲区（ring buffer），Web 端重新接入时回放最近输出，使用户看到连续的终端现场。
- [x] 与服务端断线重连后，主动上报当前仍存活的终端会话列表，使服务端恢复终端注册表。
- [x] **客户端本地持久化**：客户端将自身标识（client ID，首次注册后固定不变）与终端会话元数据持久化到本地文件。agent 进程正常关闭/崩溃/重启后，以同一身份重新注册并重新 attach 各 holder，终端现场不变。
- [x] **状态边界**：仅保证 agent 进程级别的重启不丢状态；若客户端机器本身掉电/重启，holder 随之消亡，状态允许丢失，重连后按实际存活情况上报（已消亡的终端从注册表清除）。
- [x] 文件能力：响应服务端的文件操作请求——列目录、读文件、写文件、新建、删除、重命名/移动、上传、下载。
- [x] 终端会话关闭时正确回收 holder/PTY 进程，不产生僵尸进程。
- [x] 终端重命名：标题在 agent 侧同步持久化，重启后不丢。

### 4.2 服务端（Server）

- [x] Go 实现，无数据库。`.env` 配置项包括：
  - `PORT`：Web 服务端口；
  - `ADMIN_USER` / `ADMIN_PASSWORD`：Web 控制台登录账号（单用户即可）；
  - `AGENT_KEY`：客户端注册鉴权密钥；
  - AI 配置：`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`、默认授权模式（`AI_DEFAULT_MODE`）等。
- [x] **AI 参数 Web 端可配**：「AI Agent → 模型设置」中在线修改 Base URL / Key / Model / 默认模式（含连通性测试），保存后立即生效并持久化；**Web 端保存的非空字段优先于 .env**，留空字段跟随 .env；Key 在接口返回中打码。
- [x] Web 登录鉴权：**用户名 + 密码 + 图形验证码**（base64Captcha，一次性、限时有效）。认证方式采用 **Token（JWT）** 而非 Cookie Session，以便未来 App 端直接复用同一套认证。
- [x] **登录防爆破**：连续登录失败（密码错误或验证码错误）**5 次锁定 10 分钟**，锁定期间即使凭证正确也拒绝登录并返回剩余锁定秒数；登录成功后清零失败计数。失败计数与锁定状态纳入状态持久化，服务端重启后不失效。
- [x] **API 面向多客户端设计**：所有接口（REST + WebSocket）与前端解耦、不依赖浏览器特性，统一走 `/api/v1` 版本前缀；认证 Token 通过 Header 传递。日后 App 端接入时无需改动服务端协议。
- [x] 客户端连接管理：注册、鉴权、在线/离线状态维护、心跳保活、同 ID 重复接入时顶掉旧连接。
- [x] **客户端删除**：用户可手动删除列表中**不在线**的客户端（连同其终端注册表等持久化状态一并清除）；在线客户端拒绝删除（400）。被删除的客户端若之后再次接入，以原 ID 重新注册。
- [x] 终端中继：浏览器 xterm.js ↔ WebSocket ↔ 客户端 holder 的双向转发；支持**多客户端 × 多终端同时打开**；转发 resize 事件与终端重命名。
- [x] **终端会话与 Web 连接解耦**：Web 端 WebSocket 断开（关闭浏览器、退出登录、网络抖动）不关闭终端；用户重新登录后可重新接入（reattach）任一存活终端，并收到滚动缓冲区回放以还原终端现场。同一终端支持 Web 端断开/重接任意多次。
- [x] 文件管理代理：将 Web 端的文件操作请求路由到目标客户端并返回结果。
- [x] **状态持久化（无数据库）**：服务端将全部运行状态持久化到 `DATA_DIR/state.json`，包括：客户端注册表（含别名、可用 shell 列表）、终端会话注册表、用户页面布局状态、AI 会话及其完整聊天记录、审批 allowlist、登录防爆破计数、Web 端 AI 配置等。状态变更时及时落盘，**服务端重启/崩溃后从文件完整恢复**。
- [x] **重启恢复**：服务端重启后，客户端自动重连并上报各自存活的终端；服务端将上报结果与持久化的终端注册表对账——仍存活的终端恢复可接入状态（缺缓冲的终端向 agent 请求回放），已不存在的终端标记为已关闭。AI 会话恢复全部聊天历史，重启时正在执行中的任务标记为"已中断"，用户可继续对话。用户重新登录后页面状态与重启前一致。
- [x] AI Agent 服务（见 4.3）。

### 4.3 AI Agent（逻辑参照 hermes-agent）

> 参照对象是 Nous Research 开源的 hermes-agent 项目。**参照范围仅限以下部分**，不要求照搬其记忆/技能学习闭环、TUI、插件系统等其余特性：
>
> 1. **Agent 循环**：LLM tool-calling 循环——模型输出工具调用 → 执行 → 结果回注 → 继续推理，直到任务完成或被打断；
> 2. **工具集**：面向本项目的工具，如在指定终端执行命令、读取终端输出、读写客户端文件等；
> 3. **授权（approval）机制**：参照 hermes 的命令审批方式——
>    - **全自动模式**：所有工具调用直接执行；
>    - **审批模式**：每条命令执行前在 Web 端弹出审批，用户可批准 / 拒绝 / 始终允许同类命令（allowlist 语义）；
>    - 授权模式可在 `.env` 或 Web 端模型设置中设默认值，并可在 Web 会话中热切换；
> 4. **上下文管理**：长会话时参照 hermes 的压缩/截断策略处理上下文溢出；
> 5. **多会话**：每个 AI 会话有独立的对话历史与目标终端集合。

功能要求：

- [x] **目标选择**：用户可选择一个、多个或全部客户端的具体终端作为该会话的操作目标；AI 的工具调用会被路由到对应客户端的对应终端执行；目标集合之外的终端/文件操作会被拒绝（目标越权防护，经真实模型验证）。
- [x] **多会话**：可同时存在多个 AI 会话，互不干扰；会话支持重命名与删除（列表右键菜单）。
- [x] **多目标执行**：面向多个终端时，支持并行下发执行并汇总各终端结果给模型；支持有数据依赖的跨机协同（A 机产出 → 搬运到 B 机，含跨平台）。
- [x] 执行过程与工具调用结果在 Web 端实时展示（Markdown 完整渲染：GFM 表格/代码块/列表等）；工具调用与结果标注目标终端（客户端:终端）；每条消息气泡带时间戳；用户可随时中断（interrupt）当前会话执行。
- [x] 审批模式下，挂起的审批请求在 Web 端实时推送（批准/拒绝/始终允许）；会话删除或中断时挂起审批随之清理。

### 4.4 Web 前端

- [x] **中英双语界面**：界面语言按浏览器自动检测（中文环境默认中文，其余默认英文），可随时一键切换并记忆；时间戳等本地化格式跟随语言。
- [x] **登录页**：用户名 + 密码 + 图形验证码登录；验证码可点击刷新，错误时提示并自动刷新验证码。
- [x] **客户端列表页**：展示所有已注册客户端（名称/别名、主机信息含平台、在线状态、终端数、最近在线时间）；支持给客户端起别名（内联编辑，展示优先于主机名）；每张卡片提供**终端下拉面板**（新建终端可选该客户端实际上报的 shell 类型；可一键接入该客户端的常驻终端）与文件管理入口；离线客户端可手动删除（二次确认），在线客户端无删除入口。
- [x] **终端页**：xterm.js 终端，多标签页同时打开多个客户端的多个终端；断线提示与重连。
  - **新建终端富下拉面板**：固定在标签栏右侧（标签再多也不被挤出屏幕），分"新建终端（按客户端展开 shell 类型列表）"与"接入已有终端"两区，点击外部/操作后自动关闭；
  - 标签支持双击重命名、右键菜单（重命名 / 从页面移除 / 关闭终端）；超长标签名省略号截断不换行；
  - "从页面移除"仅移除标签，终端在客户端继续常驻。
- [x] **文件管理页**：目录浏览 + 文件列表；文本文件直接在内嵌 Monaco 编辑器中查看/编辑/保存；支持上传、下载、新建、删除、重命名；切换客户端时显示名称同步更新。
- [x] **AI Agent 面板**：会话列表（新建/切换/重命名/删除，右键菜单）；聊天界面（流式输出、Markdown 渲染、消息时间戳、工具调用目标标注）；目标终端选择器（单选/多选/全选，精确到某客户端的某终端）；授权模式切换；审批请求弹窗（批准/拒绝/始终允许）；中断按钮；模型设置（Base URL/Key/Model/默认模式 + 连通性测试）。
- [x] **页面状态恢复**：用户关闭浏览器或退出登录后重新登录，页面应恢复到离开前的状态——当前页面、已打开的终端标签与激活标签（自动 reattach 到仍存活的终端并回放输出）、文件管理页的当前目录与打开的编辑器、AI 会话列表及各会话的聊天记录与目标选择。页面状态保存在服务端并随状态持久化落盘，不依赖浏览器 localStorage——换浏览器、换机器、服务端重启后均一致。

## 5. 非功能需求

- **安全**：所有 WebSocket 与 API 均鉴权；客户端密钥不匹配拒绝接入；AI 工具调用限制在会话目标集合内；AI 执行的命令与审批记录可审计（输出到服务端日志）。
- **并发**：服务端需支撑多浏览器会话 × 多客户端 × 多终端的并发 IO，单连接阻塞不得影响其他连接。
- **健壮性**：任一客户端断线不影响其他客户端；重连后状态一致；终端/文件句柄正确回收。
- **部署**：服务端与客户端均为单二进制 + `.env` 即可运行；提供构建命令（含前端产物嵌入）；客户端支持 windows/amd64、linux/amd64+arm64、darwin/amd64+arm64 交叉编译。

## 6. 约束与明确排除

- ~~客户端暂只支持 Linux / Unix-like，不考虑 Windows。~~ **已扩展为全平台**：Windows 10 1809+ / Linux / macOS（Windows 终端基于 ConPTY，需 1809 及以上版本）。
- 不使用数据库，不实现多用户/权限体系（单管理员账号，`.env` 配置）。状态持久化一律通过本地文件实现。
- 不实现 hermes 的记忆、技能自学习、插件系统、TUI 等能力。
- 终端会话为常驻会话：不随 Web 登录状态或服务端重启销毁，只有用户显式关闭或 shell 退出才结束。服务端重启后通过持久化状态 + 客户端重连上报恢复完整现场。
- 状态边界：服务端重启、客户端 agent 进程重启、网络掉线均不丢状态；仅客户端机器掉电/重启导致的状态丢失是可接受的。
- **本期不实现 App 端**，但服务端 API 与认证设计已为 App（移动端/桌面端）接入预留：协议与平台无关、Token 认证、接口版本化。App 端接入时不需要重构服务端。

## 7. 验收标准

1. 客户端凭正确密钥注册成功、错误密钥被拒绝；断线后自动重连，且以固定 client ID 重新注册为同一客户端（不产生重复列表项）。
2. **客户端 agent 重启不丢状态**：kill 掉客户端 agent 进程后重新启动——其终端会话仍存活可接入、输出连续，列表中客户端身份与在线状态正确恢复（Windows 与 Linux 均已验证）。
3. 登录需图形验证码：验证码错误/过期无法登录，正确方可通过；认证 Token 失效后接口与 WebSocket 均拒绝访问。
4. **登录防爆破**：连续失败 5 次后锁定 10 分钟，期间正确凭证也无法登录；锁定状态在服务端重启后仍然有效；成功登录后计数清零。
5. 浏览器可同时打开多台测试机（含 Windows 与 Linux 混编）的多个终端并正常交互（含全屏程序与 resize）。
6. **终端常驻**：在某终端中运行持续输出命令，关闭浏览器后重新登录——终端仍存在、进程仍在运行、重新接入后能看到离开期间产生的输出回放；只有显式关闭终端后 PTY 才被销毁。
7. **终端类型选择**：新建终端时下拉选项来自客户端实际上报的可用 shell（Windows：PowerShell/CMD/Git Bash 等；Linux：bash/zsh 等）；指定类型打开的终端确实运行对应 shell；非法 shell 被 agent 拒绝。
8. **页面状态恢复**：重新登录后，当前页面、终端标签、文件管理页位置、AI 会话及聊天记录与离开前一致。
9. **服务端重启恢复**：在终端运行持续输出命令、AI 会话有聊天记录的状态下重启服务端进程——客户端自动重连，终端仍可接入且输出连续，页面布局与 AI 聊天历史完整恢复，重启时在途的 AI 任务显示为"已中断"。
10. **客户端删除**：停掉一台测试机的 agent 使其离线，在列表中删除成功且其状态被清除；在线客户端无删除入口（API 删除在线客户端返回 400）。
11. 文件管理页可浏览各测试机文件，Monaco 可编辑并保存文本文件。
12. AI 会话中：选择单终端可完成"查看系统信息"类任务；选择多台机器终端可并行执行并汇总结果；多目标会话中指明只操作其中一台时不会越界操作其它终端。
13. 审批模式下命令逐条弹窗，批准才执行；"始终允许"后同类命令不再弹窗；切换全自动后不再弹窗。
14. AI 模型参数可在 Web 端在线修改并立即生效（连通性测试通过），且 Web 配置优先于 .env。
